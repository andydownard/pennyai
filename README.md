# thriftly

Text Penny AI to build your family's shopping list.

## What you need

1. **Go** — the programming language ([download](https://go.dev/dl/))
2. **Node.js** — for building the frontend ([download](https://nodejs.org/))
3. **PostgreSQL** — a local database (the app and the test tiers use it)
4. **A Clerk instance** — sign-in is Rally's, through Clerk ("Continue with Rally"). For local work you can skip it and use `TEST_MODE=true` (see below).

## Signing in

Sign-in is Clerk only. Set `CLERK_ENABLED=1`, `CLERK_JWT_ISSUER` and `CLERK_AUTHORIZED_PARTIES` (see `.env.example`). The backend verifies Clerk's session JWT against the issuer's public JWKS and then mints its own session cookie. Never put `CLERK_SECRET_KEY` or `CLERK_WEBHOOK_SIGNING_SECRET` in this app's environment; it refuses to start if either is set. The Clerk instance should emit the custom session-token claims `email` and `name`. Groflo stores no phone numbers.

For local development without Clerk, set `TEST_MODE=true`. That enables `POST /auth/test-login`. It is refused on Railway.

## Running locally

```bash
# 1. Clone the repo
git clone https://github.com/YOUR_USERNAME/thriftly.git
cd thriftly

# 2. Create your .env file
cp .env.example .env
# Open .env in any editor and fill in the values you need

# 3. Install Go dependencies (one time)
go mod tidy

# 4. Build the frontend (one time, and after frontend changes)
cd frontend
npm install
npm run build
cd ..

# 5. Run the server
source .env && go run .
```

Visit **http://localhost:8080** — you should see the login screen.

## Running tests

Tests don't need Clerk credentials. The Go suite runs on real PostgreSQL (the only database). Each test gets its own database cloned from a template built by the production schema. It needs a local server where your user may CREATE DATABASE; set `TEST_DATABASE_URL` to point elsewhere (default `postgres://localhost:5432/postgres?sslmode=disable`):

```bash
go test -count=1 ./...        # whole suite, one process
scripts/test-postgres.sh      # same suite in parallel chunks (faster; used locally to find panics)
# or: TEST_DATABASE_URL=postgres://user:pass@host:5432/postgres?sslmode=disable go test -count=1 ./...
go test -race                 # detect concurrency bugs
cd frontend && npx playwright test   # end-to-end; uses a throwaway local Postgres database and TEST_MODE=true
```

CI runs the Go suite against a `postgres:16` service container, plus the frontend checks.

## How your API keys stay safe

This is important to understand:

- **Your credentials (Anthropic and the rest) are ONLY in your .env file**, which is listed in `.gitignore` — git will never track it, so it can't accidentally end up on GitHub.
- **The Go server loads them from environment variables** at startup. They live in server memory and are never exposed via any URL endpoint.
- **The frontend (React) NEVER sees your keys.** All third-party API calls happen server-side in Go. The browser only talks to your Go server, which talks to those services on its behalf. The only values in the frontend build are the public `VITE_*` ones, such as the Clerk publishable key.
- **Session cookies are HttpOnly**, meaning JavaScript running in the browser can't read them — this prevents XSS attacks from stealing sessions.

```
Browser  →  Your Go server  →  Third-party APIs
  (no keys)     (has keys)       (checks keys)
```

If someone hacks into your GitHub repo, they won't find any secrets because `.env` is never committed.

## Project structure

```
thriftly/
├── server.go, handlers_*.go, ...  ← Go backend (package main; run with `go run .`)
├── clerk*.go          ← Clerk token verification and local user upsert
├── pgcompat.go        ← legacy-SQL-dialect-to-PostgreSQL SQL wrapper
├── *_test.go          ← Go tests (run on PostgreSQL; see Running tests)
├── go.mod             ← Go dependencies (module is still named thriftly)
├── .env.example       ← Template — copy to .env and fill in
├── Dockerfile         ← Builds the frontends and the Go binary; takes VITE_* build args
├── railway.toml       ← Railway deploy settings
├── frontend/          ← Consumer React app (Vite); Playwright tests in e2e/
├── frontend-brand/    ← Brand portal React app
├── marketing/         ← Marketing site
├── static/            ← Built consumer frontend (generated by npm run build)
└── static-brand/      ← Built brand portal (generated)
```

## Development workflow

For faster iteration on the frontend (hot reload):

```bash
# Terminal 1: Go server
source .env && go run .

# Terminal 2: Vite dev server (auto-refreshes on changes)
cd frontend
npm run dev
```

Visit **http://localhost:5173** during development. Vite proxies `/auth/*` requests to the Go server automatically.
